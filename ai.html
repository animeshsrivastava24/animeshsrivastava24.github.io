AI projects

I use LLM agents to automate firmware root-cause analysis on Snapdragon modem software, from race-condition detection in multi-threaded modem flows to RF front-end conflict triage.

16×faster RFFE conflict debug
3–4×faster crash root-cause analysis
~2.7×faster OEM field-issue triage

Debug agents at Qualcomm

Each agent is a harness (the loop that reads logs, calls tools and keeps state, built with LangGraph) around a language model that does the reasoning. They are internal systems, so the work is described here but the code is not public.

Agent 1, LangGraph

Cross-thread timeline reconstruction

3–4×faster root-cause analysis
1Problem
Race conditions behind late-surfacing modem crashes took 3–4 days to root-cause. The evidence is spread across many firmware threads, each with its own log.
2Solution
A LangGraph agent that rebuilds one timeline across firmware threads, maps lock-free producer–consumer dependencies and flags tight timing gaps that can become races under load. Engineers start from a suspect window instead of raw logs.

Agent 2, agentic RAG

RFFE conflict debugger

16×faster debug, about 2 days to 1 hour
1Problem
An RFFE conflict failure took about two working days to debug by hand: checking band combinations against 3GPP, comparing software releases and tracing which RF front-end resources collide.
2Solution
A planner with three sources of truth. It retrieves 3GPP band-combination rules, diffs the previous and current release, and checks the physical-to-logical RFFE device map before giving a verdict.

Agent 3, multi-agent

OEM field-issue triage

~2.7×faster triage
1Problem
Field issues reported by phone makers arrive as large crash logs. Matching them against known issues one by one was slow and manual.
2Solution
A multi-agent system that extracts crash signatures once, then runs several matchers against known-issue sets in parallel and ranks the results into a likely root cause and next debug steps.

MCP servers

The Model Context Protocol lets an AI assistant call real tools. These two give it the context embedded work needs. Both are in progress, and this page will link to their repositories when they are public.

In progress

regmap-mcp

Register maps, not guesses. LLMs often invent register bit positions. regmap-mcp loads CMSIS-SVD files for STM32 parts and answers from the vendor's own register map: peripherals, registers, fields and reset values.

list_peripherals(device)get_register(device, periph, reg)decode(device, periph, reg, value)encode(device, periph, reg, fields)
PythonMCP SDKCMSIS-SVDSTM32
In progress

faultdump-mcp

Post-mortems for Cortex-M crashes. Takes a HardFault dump captured over UART (stacked registers plus CFSR, HFSR, MMFAR and BFAR), decodes the fault cause and maps PC and LR back to source lines using the ELF file.

decode_fault(dump)stack_frame(dump)symbolize(addr, elf)last_faults(n)
PythonMCP SDKARM Cortex-MELF / DWARF
